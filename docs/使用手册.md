## 1. 站点结构总览

| 文件夹/文件 | 用途 | 你该不该动 |
|---|---|---|
| `src/pages/posts/*.md` | 所有文章 | ✅ 经常改 |

## 2. 写文章

### 文章格式

每篇文章是一个 `.md` 文件，放在 `src/content/posts/` 目录下。

**文件名格式**：`YYYY-MM-DD-标题.md`（日期+标题，用英文或拼音）

**文件内容**：

```markdown
---
title: "文章标题"
description: "一句话摘要，显示在卡片和文章头部"
published: 2026-10-05
tags: ["Web安全", "XSS"]
---

## 第一个二级标题

正文内容，支持所有 **Markdown** 语法。

- 列表项
- 列表项

> 引用块

`代码行`

```python
# 代码块
print("hello")
```

[链接](https://example.com)

![图片](/images/xxx.png)
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 标题 |
| `description` | ✅ | 摘要 |
| `published` | ✅ | 发布日期 |
| `tags` | ❌ | 标签数组 |
| `draft` | ❌ | `true` 则不发布 |
| `cover` | ❌ | 封面图路径 |
| `category` | ❌ | 分类 slug |

### 写文章步骤

**方式一：在 GitHub 上写**

1. 打开 https://github.com/TANGJIN13/tangjin-blog/tree/main/src/content/posts
2. 点 **Add file** → **Create new file**
3. 文件名：`2026-10-05-文章标题.md`
4. 填入上面的格式内容
5. 往下滚，点绿色 **Commit changes**
6. 等 1-2 分钟自动上线

**方式二：在 Obsidian 里写**

1. Obsidian 打开 `src/content/posts/` 文件夹
2. 新建笔记，按上面的格式写
3. 装 Obsidian Git 插件 → 保存自动同步到 GitHub

**方式三：本地编辑器（VS Code 等）**

1. 在 `src/content/posts/` 新建 `.md` 文件
2. 保存
3. 运行 `git add . && git commit -m "post: 标题" && git push`

### 支持的 Markdown 扩展

| 语法 | 效果 |
|---|---|
| `## 标题` | 二级标题 |
| `**粗体**` | 粗体 |
| `` `code` `` | 行内代码 |
| ` ```lang ` | 代码块（带高亮） |
| `> 引用` | 引用块 |
| `- 列表` | 无序列表 |
| `![alt](/path)` | 图片 |
| `[文本](url)` | 链接 |

## 3. 文章分类管理

### 分类定义

编辑 `src/data/categories.ts`：

```ts
export const categories = [
  { name: 'Web 安全', slug: 'web-security', description: 'Web 安全相关文章', icon: 'lock' },
  { name: 'CTF', slug: 'ctf', description: 'CTF 题解与笔记', icon: 'flag' },
];
```

每个分类有 4 个字段：

| 字段 | 含义 | 示例 |
|---|---|---|
| `name` | 显示的名字 | `'Web 安全'` |
| `slug` | 网址用的英文标识 | `'web-security'` |
| `description` | 一句话说明 | `'Web 安全相关文章'` |
| `icon` | 图标名 | `'lock'` / `'flag'` / `'text'` / `'code'` |

### 加分类

在数组末尾加一行：

```ts
{ name: '逆向', slug: 'reverse', description: '逆向工程笔记', icon: 'code' },
```

### 删分类

删掉对应那行。

### 给文章指定分类

在文章 frontmatter 里加：

```yaml
category: web-security
```

## 4. 友链管理

### 友链数据

编辑 `src/pages/friends.astro`，找到 `friends` 数组（约第 13 行）：

const friends: Friend[] = [

每个友链有 4 个字段：

| 字段 | 含义 | 怎么获取 |
|---|---|---|
| `name` | 显示的名字 | 对方站名 |
| `url` | 友链网址 | 对方提供的链接 |
| `avatar` | 头像图片地址 | 对方的头像 URL |

复制一行，改内容：

```ts
  { name: '朋友名字', url: 'https://朋友网址/', avatar: '头像链接', description: '一句话介绍' },
```

### 删友链

删掉对应那行。

### 改友链

改对应行的字段值。

## 5. 音乐播放器

### 当前配置

播放器支持两种模式：
- **本地 MP3**：文件放在 `public/music/`
- **外链（Meting.js）**：QQ音乐/网易云/酷狗

### 加本地歌曲

1. 把 MP3 文件复制到 `public/music/`
2. 编辑 `src/components/MusicPlayer.astro`，找到 `localTracks` 数组，加一行：

```js
{ name: '歌名', artist: '歌手', url: '/music/文件名.mp3' },
```

### 加外链歌单（推荐）

编辑 `src/components/MusicPlayer.astro`，找到 `metingSongs` 数组：

```js
const metingSongs = [
  { server: 'netease', type: 'playlist', id: '网易云歌单ID' },
];
```

**怎么获取歌单 ID**：
- 网易云：`music.163.com/playlist?id=**12345678**` → ID 是 `12345678`
- QQ音乐：`y.qq.com/n/ryqq/playlist/xxxxx` → ID 是 `xxxxx`

**怎么获取单曲 ID**：
- 网易云单曲：`music.163.com/song?id=**12345678**`
- 只能加**免费**歌曲，VIP 歌不能外链

### 本地 + 外链混用

```js
const metingSongs = [
  { server: 'netease', type: 'playlist', id: '免费歌单ID' },
];
const localTracks = [
  { name: 'VIP歌名', artist: '歌手', url: '/music/vip.mp3' },
];
```

播放器优先使用外链，没有外链时播放本地。

## 7. 站点配置

编辑 `src/site.ts`：

```ts
export const site = {
  title: 'tj',                    // 导航栏名字
  tabTitle: "tj's Blog",          // 浏览器标签标题
  description: '...',             // 站点描述（SEO用）
  motto: '凡心所向，素履以往',     // 首页大字
  mottoSub: '生如逆旅，一苇以航',  // 首页小字
  icp: '桂ICP备2026005024号-1',   // 备案号
  startDate: '2026-10-04',         // 建站日期（运行时长计算用）
  footer: { since: 2026 },         // 页脚起始年份
};
```

### 改什么 → 改哪个字段

| 要改什么 | 改哪个字段 |
|---|---|
| 导航栏左上角的 `tj` | `title` |
| 浏览器标签的 `tj's Blog` | `tabTitle` |
| 首页大标题 | `motto` |
| 首页小标题 | `mottoSub` |
| 页脚备案号 | `icp` |
| 页脚起始年份 | `footer.since` |

images = [

  '/images/wallpapers/你的新壁纸.svg',  // ← 加这行

```

## 10. 部署上线

### 推送代码

改完文件后，推送到 GitHub：

```bash
git add .
git commit -m "描述你改了什么"
git push
```

或者在 GitHub 网页上直接编辑文件 → 点 **Commit changes**。

### 自动部署流程

```
你 push 代码 → GitHub Actions 自动触发
    ↓
1. 拉取代码
2. 安装 Node.js + pnpm
3. 构建站点（pnpm build）
4. rsync 推送到服务器
5. nginx 提供服务
    ↓
约 1-2 分钟后 https://tangjin.xyz 更新
```

### 查看部署状态

打开 https://github.com/TANGJIN13/tangjin-blog/actions 可以看到构建进度和是否成功。

## 11. 常见问题

### 改完没生效？

1. **浏览器缓存**：按 `Ctrl + Shift + R` 强刷
2. **GitHub Actions 还在跑**：去 https://github.com/TANGJIN13/tangjin-blog/actions 看进度
3. **构建失败**：Actions 页面会显示错误信息

### 页面 404？

- 检查文章文件名格式：`YYYY-MM-DD-标题.md`
- 检查 frontmatter 格式：`---` 开头结尾，`published: YYYY-MM-DD`

### 构建失败？

去 GitHub Actions 看错误信息，常见原因：
- YAML 格式错（冒号后面要有空格）
- 文件名拼写错
- frontmatter 缺少必填字段

### 本地预览？

```bash
cd tangjin-blog
pnpm install
astro dev --background
# 打开 http://localhost:4321
```
