### 内容层 API（重要）

Astro 7 的 content layer 与旧版不同，正确用法：

```ts
// src/content.config.ts
import { defineCollection } from 'astro:content';
import { glob } from 'astro/loaders';
// z 要从 astro/zod 导入（astro:content 里的 z 已 deprecated）
import { z } from 'astro/zod';

posts: defineCollection({
  loader: glob({ pattern: '**/*.{md,mdx}', base: './src/content/posts' }),
  schema: z.object({
    title: z.string(),
    description: z.string(),
    published: z.coerce.date(),
    updated: z.coerce.date().optional(),
    tags: z.array(z.string()).default([]),
    draft: z.boolean().optional(),
    category: z.string().optional(),
    cover: z.string().optional(),
  }),
});
```

**关键区别**：entry 没有 `.render()` 方法，必须用顶层 `render(entry)`：

```ts
import { render } from 'astro:content';
const { Content } = await render(post);
// getCollection 返回 Promise，必须 await
const posts = await getCollection('posts');
```

## 5. 部署流程

### 方式一：本地 Markdown + 一键推送

```bash
# 在 src/content/posts/ 里新建 .md 文件
# 然后双击 push.cmd
```

`push.cmd` 会自动：检测网络 → 提交 → 同步远程 → 推送 GitHub → Actions 自动部署。

### 方式二：本地构建直传服务器

双击 `deploy.cmd`，本地构建后直接 scp 到服务器（不走 GitHub）。

### 方式三：纯 git 命令

```bash
cd C:\Users\liang\Documents\deepseek-harness\default-workspace\tangjin-blog
git add .
git commit -m "post: 新文章"
git push  # 如果直连失败会自动走代理
```

### 部署关键陷阱

| 陷阱 | 原因 | 解决 |
|---|---|---|
| Windows scp 上传目录权限变 700 | Windows scp 不保留权限 | 部署脚本已自动 chmod 755/644 |
| 直连 github.com 被重置 | GFW 干扰 | push.cmd 自动切换本地代理 127.0.0.1:7897 |
| rsync 目标路径写错 | rrsync 限制路径语义 | 工作流已写 `:/` 而非 `:$DEPLOY_PATH/` |

## 8. 安全模型

### 加固：部署密钥限制为 rrsync 只写

服务器 `~/.ssh/authorized_keys` 中部署密钥行：

```
command="/usr/bin/rrsync -wo /var/www/blog",restrict ssh-ed25519 AAAA... github-actions-deploy@tangjin.xyz
```

实测限制：

| 尝试 | 结果 |
|---|---|
| 执行 `whoami` / `cat /etc/passwd` | ❌ `does not run rsync` |
| rsync 写站点目录 | ✅ 正常 |
| 写到 `/../etc/` | ❌ `do not use .. in arg` |
| 读取站点文件 | ❌ `reading from write-only server is not allowed` |

### 攻击链被封堵

```
加固前：Token 泄露 → 改工作流打印私钥 → SSH → 免密 sudo → root
加固后：Token 泄露 → 改工作流打印私钥 → 只能 rrsync 写 /var/www/blog
                                   → 不能执行命令、sudo、读文件
```

### 仍需要注意

1. **Token 权限最小化**：GitHub Token 用 Fine-grained，只给 `tangjin-blog` 的 `Contents: Read and write`，设有效期
2. **`--delete` 的危险性**：部署用 rsync --delete 会清理目标目录多余文件。目标被 rrsync 锁死在站点根，只影响站点目录。手动 rsync 务必确认路径
3. **本机私钥备份**：`deploy-key/github-actions-deploy` 是备份，泄露则删服务器 authorized_keys 对应行

## 9. 常见问题排查

### 页面 403

原因：目录权限不是 755（Windows scp 会建成 700）

```bash
# 服务器上
find /var/www/blog -type d -exec chmod 755 {} +
find /var/www/blog -type f -exec chmod 644 {} +
```

### push 报 non-fast-forward

原因：本地没拉远程（在 GitHub 网页上改过文件）。`push.cmd` 会自动 pull --rebase，用 push.cmd 就不会。

### push 报 Connection was reset

原因：直连被墙。push.cmd 自动切换本地代理 127.0.0.1:7897。

### Actions 报错 SSH_PRIVATE_KEY

原因：缺 Secret。仓库 Settings → Secrets and variables → Actions → 添加 SSH_PRIVATE_KEY。

### 改了没生效

原因：Actions 还在跑。查看：https://github.com/TANGJIN13/tangjin-blog/actions

### favicon 没变

原因：浏览器缓存。Ctrl+Shift+R 强刷，或关标签页重开。新图标文件名带版本号（icon-3.ico），换图标时改版本号可破缓存。

### 文章页 404

原因：文章 slug 与文件名不匹配，或 draft: true。

## 10. 应急处理

### 私钥泄露

```bash
# 1. 服务器上删掉部署密钥那一行
ssh tangjin "sed -i '/github-actions-deploy/d' ~/.ssh/authorized_keys"

# 2. 重新生成部署密钥对
ssh-keygen -t ed25519 -f github-actions-deploy -N '' -C "github-actions-deploy@tangjin.xyz"

# 3. 公钥加回服务器（带 rrsync 限制）
PUB=$(cat github-actions-deploy.pub)
ssh tangjin "echo 'command=\"/usr/bin/rrsync -wo /var/www/blog\",restrict $PUB' >> ~/.ssh/authorized_keys"

# 4. 更新 GitHub Secret（仓库 Settings → Secrets → SSH_PRIVATE_KEY）
#    把 github-actions-deploy 的全文粘贴进去
```

### 站点被清空

```bash
# 双击 deploy.cmd（本地构建直传，不走 GitHub）
# 或
cd tangjin-blog
pnpm build
scp -r dist/* tangjin:/var/www/blog/
ssh tangjin "find /var/www/blog -type d -exec chmod 755 {} +; find /var/www/blog -type f -exec chmod 644 {} +"
```
